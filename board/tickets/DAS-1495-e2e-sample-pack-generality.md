## Description

**What:** Prove the WS7 GATEWAY end-to-end by authoring a small but *real* Project-OS pack, running `scripts/gateway_compile.py` on it, and demonstrating it compiles into a coherent, self-contained story-ticket board — then repeating with a second, different pack to prove generality (no gateway code changes).

**Why:** This is the GATE-4 Testing (P22, §5 row 10) validation for the gateway machinery. The gateway's value claim is that a Project-OS pack compiles into an executable board of coherent story tickets with zero hand-written tickets. That claim must be demonstrated on real input, not asserted, and must hold across at least two distinct packs to show the compiler generalizes rather than special-casing one fixture.

**Embedded context:** The ORGANISM WS7 GATEWAY (spec-of-record `docs/research/ORGANISM-PROGRAM-PLAN.md`) turns a Project-OS pack (`docs/specs/PROJECT-OS-PACK.md`) into board tickets through `scripts/gateway_compile.py`. Every compiled ticket must be a coherent self-contained story ticket carrying: embedded context, acceptance criteria, produces/consumes edges, its AADL stage, and a gate reference (per the six-stage lifecycle in `governance/policies/ai-agent-lifecycle.md`). Compiled tickets from a sample pack are SCRATCH — they land on a scratch/tmp project board, NEVER the org `board/tickets/`.

**Extend vs. new:** Extend the existing evals tree — add `evals/e2e/sample-pack/` and `evals/e2e/sample-pack-2/` and their e2e test(s). Reuse `scripts/gateway_compile.py` unchanged (changing it to make pack-2 pass would defeat the generality check). Do not fork the compiler.

**Key files + paths:**
- `scripts/gateway_compile.py` — the compiler under test (READ; do not modify for pack-2).
- `docs/specs/PROJECT-OS-PACK.md` — Project-OS pack format (manifest + `docs/01-planning`..`docs/06-maintenance` + discovery answers + `APPROVED-GOAL-QUEUE.md`).
- `governance/policies/ai-agent-lifecycle.md` — six-stage AADL / gate references embedded in each compiled ticket.
- `docs/research/ORGANISM-PROGRAM-PLAN.md` — spec-of-record.
- `evals/e2e/sample-pack/` — pack 1 (e.g. a CRUD SaaS with auth + one integration): `PROJECT-OS.yaml` manifest + `docs/01-planning`..`docs/06-maintenance` + discovery answers + `APPROVED-GOAL-QUEUE.md`.
- `evals/e2e/sample-pack-2/` — pack 2, a *different* domain, same format.

**Scope:** Author `evals/e2e/sample-pack/` as a real (not stub) Project-OS pack for a small product such as a CRUD SaaS with auth plus one external integration. Run `gateway_compile.py` on it and demonstrate it produces **>= 25 coherent self-contained story tickets** with **zero hand-written tickets** — every ticket generated by the compiler and each carrying embedded context, acceptance, produces/consumes, AADL stage, and gate ref. Then author a second, materially different pack in `evals/e2e/sample-pack-2/` and show it compiles **without any gateway code changes**, proving generality. Compiled boards land on a scratch/tmp project board, not the org board. Document honestly that the compile + validation is what is proven here, and that the full 0->100 delivery through all six gates to a deployable artifact is the *scaled operation the gateway enables*. Add e2e tests.
