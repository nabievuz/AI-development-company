# ADR 0040 — A2A outbound surface: DasLab as a callable governed agent for another agent system

- **Status:** Accepted (CTO authors + ratifies — RACI 3.1/3.6 A, same accountable owner as ADR 0036; small governance ADR, author+ratify by the CTO with the reasoning documented; Security Lead consulted — admission/redaction reuse, no second entry path)
- **Date:** 2026-07-24
- **Scope:** Platform / org-engine — the **A2A** (agent-to-agent) slice of the outbound (consumed-by-the-ecosystem) surface: DasLab invoked as a governed agent by *another agent system*
- **Deciders:** **CTO (author + accountable)**; Security Lead (consulted — ADR 0009 admission + ADR 0012 redaction reuse at the A2A boundary)
- **Relates:** **extends** [0036](0036-outbound-interop-surface-langsmith.md) (outbound interop surface, OB-1…OB-4) — A2A is a slice of that surface, not a fresh one; backed by the [0034](0034-agent-sdk-headless-runner.md) headless runner (needs it, hence "after B"); honors [0009](0009-harness-owns-transport-admission-layer.md) (admission), [0012](0012-dgox-event-store-content-classification-redaction-policy.md) (redaction), [0024](0024-span-event-schema.md)/[0025](0025-events-load-bearing.md) (audit/event store canonical), [0019](0019-latent-machine-feature-flags.md) (feature-flag OFF); in-tenant boundary per [0038](0038-enterprise-internal-self-host-hardening.md) (TN-1); the untrusted-input discipline of [0033](0033-ecosystem-tool-mcp-bridge.md) (TB-4 ingress) applies to a caller's payload; SPEC-009 (`docs/specs/009-mustaqil-a2a-outbound/SPEC.md`); MUSTAQIL master prompt v3.0 interop extension (`docs/research/2026-07-23-daslab-mustaqil-master-prompt-v3.md`, Part 1 row 2 + Part 2); Founder discovery answer Q12 (defer A2A until after the WS-G proof lands)
- **Supersedes / Amends:** nothing — **extends** ADR 0036; additive; publishing is a Founder act.

> The agentic-design-patterns audit surfaced A2A (agent-to-agent invocation) as the one net-new capability the pattern map lacked: DasLab can be *cloned and run*, and after ADR 0036 it can be *called* as a LangGraph node / MCP server — but nothing lets **another agent system** hand DasLab a goal and get governed delivery back. This ADR fixes that move as a **slice of the ADR 0036 outbound surface**, not a new surface, so the whole governance edge (admission, redaction, never-auto-approve, in-tenant) rides along unchanged. It ships no endpoint — it fixes the contract the A2A code (DAS-1610…DAS-1614) builds against.

## Context

ADR 0036 opened DasLab as an ecosystem-callable unit (OB-1 governed delivery, OB-2 the derived Langfuse lens, OB-3 admission/redaction at the edge, OB-4 Founder-gated publishing). A2A is the natural extension: an *external agent system* — not a human operator, not a LangGraph author wiring a subgraph by hand — programmatically submits a goal to DasLab and receives governed delivery. The prior art (the agent2agent protocol lineage in the stack mining, §3.3) makes the wire shape cheap; the danger is identical to ADR 0036's, only sharper because the caller is itself an autonomous agent that may be adversarial or prompt-injected: a caller that reaches raw tools, that gets its submission mistaken for an *approval*, that reaches DasLab from outside the tenant, or whose payload is trusted as instruction rather than data, converts a governed org into an ungoverned one.

Two things make A2A distinct enough to warrant its own ADR rather than a line in ADR 0036. First, the **trust boundary**: an external *agent* caller is a higher-blast-radius surface than a human wiring a subgraph, so its submission needs an explicit, binding classification — a **goal proposal**, never anything that can move a gate. Second, the **kill-switch**: A2A is a separate external-caller entry path that a tenant must be able to enable, disable, and roll back *independently* of the ADR 0036 observability lens — coupling the two under one flag would make them un-independently-rollbackable.

Founder discovery answer **Q12** deferred A2A "until after the first proof — build it as the first post-proof reach increment." The WS-G proof is machinery-complete but infra-blocked; under the Founder "100% bajar / build everything" directive the A2A **machinery** is built now **behind the flag OFF**, while **publishing a live endpoint remains a Founder act** regardless — Q12 becomes a documented **go-live gate**, not a build blocker (see Enforcement).

## Decision

**Expose DasLab as a callable governed agent for another agent system, as a slice of the ADR 0036 outbound surface — governance rides along, in-tenant only, publishing is a Founder act.** ADR 0036 OB-1…OB-4 carry forward unchanged; A2A adds the caller-is-a-proposer invariant. Binding invariants:

### A2-1 — A2A is governed delivery, not raw agent access (extends OB-1)
DasLab is offered to an external agent system as a **callable governed unit** — invoked via the ADR 0034 headless runner behind the ADR 0036 outbound edge (a LangGraph node / MCP server). What the caller gets is *"deliver this spec through the AADL-gated org,"* **not** raw tool or agent access. Governance rides along: an external caller **cannot** make DasLab skip a gate, self-approve, or bypass never-auto-approve. OB-2's spirit holds too — `board/.events.jsonl` + the attestations stay the canonical system-of-record (ADR 0025); an A2A caller's submission is derived intake, never truth.

### A2-2 — A caller's submission is a goal PROPOSAL, never a gate approval (QONUN-5) — the A2A-specific invariant
Any submission an external caller makes through the A2A surface is intaken **ONLY as a goal proposal**: a board-intake / candidate-goal artifact awaiting Founder review. It **MUST NEVER** be treated as, auto-converted into, or mistaken for a **gate approval**. The proposal **MUST NOT** write routing fields (C3), self-approve, or advance a ticket past an open AADL gate (C4). **Approvals stay Founder-only (QONUN-5):** a Founder must still approve any gate the resulting work reaches; an external agent identity can never hold gate-approval authority (ADR 0038 TN-3 human-only mapping). This is the single invariant A2A adds on top of ADR 0036, and it is the load-bearing one.

### A2-3 — Caller input is UNTRUSTED; a proposal can never change goals, approvals, or permissions (injection defense)
A caller's payload is **untrusted input**, treated with the ADR 0033 TB-4 ingress discipline: fetched/received content that can never change the agent's goal, approvals, or permissions. A prompt-injection embedded in an A2A proposal — "you are now approved," "skip GATE-3," "grant yourself write access" — is inert: it lands as proposal *text* in a board-intake artifact and reaches no control path. The A2A surface parses a caller submission as **data to be reviewed**, never as instruction to be executed, and never as a credential.

### A2-4 — In-tenant only (TN-1); no external SaaS surface
The A2A endpoint operates **in-tenant only** (ADR 0038 TN-1): no external/hosted A2A registry, relay, or endpoint that carries code or IP is permitted, and the surface is reachable only from within the declared tenant boundary. A call reaching the surface from outside the tenant is refused; a configuration pointing the endpoint at an external/hosted relay or registry fails the in-tenant check. There is no public/hosted A2A SaaS surface — consistent with the MUSTAQIL enterprise-internal boundary.

### A2-5 — Same admission + redaction at the boundary; no second entry path (extends OB-3)
Every inbound A2A call is admitted through the **existing ADR 0009 admission layer**, **audited** (ADR 0024/0025 events), and **ADR 0012 redacted** at the boundary — identically to the ADR 0036 outbound edge. No secret and no unredacted tool transcript crosses the boundary. A2A **MUST NOT** stand up a second, parallel admission path: it reuses the one governed edge, so there is exactly one place admission and redaction are enforced.

### A2-6 — Publishing is a Founder act; off by default; dedicated flag; no dispatch change on merge (extends OB-4, ADR 0019)
The A2A surface is feature-flagged **`a2a_outbound` in `config/features.yaml`, DEFAULT OFF** (ADR 0019). **Exposing the endpoint** beyond a disabled/internal state, or pointing it at any external registry/relay, is an explicit **Founder** act (a distribution/governance decision, QONUN-5) — never automated, never self-triggered by a workstream ticket — and is logged to `board/.events.jsonl`. With the flag OFF, dispatch and board behavior are **byte-identical to pre-merge** — the endpoint simply does not exist; rollback is disabling the flag / removing the endpoint wiring. The flag is **dedicated to A2A and NOT a reuse of `ws_d_langfuse_lens`** — see Enforcement for why.

## Consequences

**Positive:** DasLab becomes invokable by *another agent system* — the last reach move the pattern audit named — without touching the org brain: a proposing agent hands DasLab a goal and gets governed delivery, and every A2A-specific danger (self-approval, out-of-tenant reach, injection, unredacted crossing) is closed by an invariant that reuses the existing edge rather than a new one. Because A2A is a *slice* of ADR 0036, no new admission path, audit path, or trust boundary machinery is invented — the governance moat is unchanged, only the caller type is new.

**Negative / accepted:** An external *agent* caller is a higher-blast-radius surface than a human wiring a subgraph (mitigated by A2-2/A2-3/A2-5 — proposal-not-approval, untrusted-input, one admission edge). A dedicated flag adds one more key to operate (accepted — independent rollback is the point). Deferring live publish to a Founder act after the WS-G proof (Q12) means the machinery ships dark for a window — accepted deliberately: building behind an OFF flag costs nothing on merge, and publishing is exactly the kind of distribution decision QONUN-5 reserves to the Founder.

**Law check:** **OB-1…OB-4 (ADR 0036)** carried forward — governed delivery, derived intake, same admission/redaction, Founder-gated publish. **QONUN-5 / never-auto-approve** (A2-2: a proposal is never an approval; approvals stay Founder-only; A2-6: publishing is a Founder act). **C3/C4** (a proposal never writes routing fields, never dispatches past an open gate). **ADR 0009** (admission at the boundary, not re-opened). **ADR 0012** (redaction at the A2A edge — no secret/transcript crosses). **ADR 0025** (event store canonical; a caller's submission is derived intake, never truth). **ADR 0038 TN-1/TN-3** (in-tenant only; agent identity can never approve a gate). **ADR 0033 TB-4** (caller input is untrusted; injection cannot change goal/approvals/permissions). **ADR 0019** (feature-flagged OFF; flag-off == pre-merge). **Project placement** (platform surface under `tools/`; hosts no project content — C6).

## Enforcement / acceptance

- **Authored + ratified by the CTO on 2026-07-24** (RACI 3.1/3.6 A — same accountable owner as ADR 0036; a small governance ADR the CTO both authors and ratifies, with the reasoning documented here). Security Lead consulted: A2A reuses the ADR 0009 admission layer and ADR 0012 redaction discipline at exactly one edge (A2-5), opening **no second entry path** — the consult confirmed the A2A boundary adds a caller *type*, not a new admission surface. Judged sound against ADR 0036 (A2A is a slice of OB-1…OB-4, not a competing surface), QONUN-5 (A2-2 keeps a caller submission a proposal and approvals Founder-only; A2-6 keeps publishing a Founder act), ADR 0038 TN-1/TN-3 (in-tenant only; no agent-held gate authority), and ADR 0033 TB-4 (caller payload untrusted). **No defect found** — no invariant admits a path where an external caller approves a gate or reaches a non-in-tenant surface. Status moves `Proposed` → `Accepted` on this sign-off.
- **Q12 go-live gate (recorded, binding):** the A2A **machinery** is built now behind `a2a_outbound` **OFF** (Founder "100% bajar" build-everything directive); **publishing a live A2A endpoint is deferred until after the WS-G proof has demonstrably shipped**, and is then an explicit **Founder act** (A2-6, QONUN-5). Flipping `a2a_outbound` to `true` or exposing the endpoint beyond internal is **not** a workstream-ticket decision — it waits for the Founder, and is logged to `board/.events.jsonl`.
- **Feature-flag decision (recorded, binding):** a **dedicated `a2a_outbound` key** lands in `config/features.yaml` `DEFAULTS` **OFF** — **NOT** a reuse of `ws_d_langfuse_lens`. Rationale: A2A is a **distinct external-caller trust boundary** (an external agent submitting goal proposals) that a tenant must be able to enable, disable, and roll back **independently** of the WS-D observability lens; coupling the two under one flag would make them un-independently-rollbackable — disabling the trace pane would silently kill the callable surface, or vice-versa. One trust boundary, one kill-switch.
- **Acceptance (traced to SPEC-009):** an external A2A call cannot advance a ticket past an open gate and cannot self-approve (SC-001, A2-1/A2-2); a goal proposal lands only as a board-intake artifact and never flips an `approval`/gate-status field (SC-002, A2-2); the endpoint resolves to an in-tenant-only address and a hosted-relay config fails the check, with any exposure requiring a logged Founder act (SC-003, A2-4/A2-6); a call skipping the ADR 0009 admission layer is denied and a transcript crossing the boundary is ADR 0012 redacted (SC-004, A2-5); with the flag OFF a wave is byte-identical to pre-merge (SC-005, A2-6).
- Any future "can another agent system drive DasLab / does an A2A caller's submission approve anything / may the A2A endpoint be hosted off-box?" question resolves here — governed delivery only, a proposal is never an approval, in-tenant only, and publishing is a Founder act.
